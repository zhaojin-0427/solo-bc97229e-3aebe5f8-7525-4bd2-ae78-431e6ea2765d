# 水库公示表格采集系统（Hydro Table Collector）

把水库公示网页中的**合并单元格 HTML 表格**转换为可入库的**结构化观测记录**，
提供从 URL 抓取、表格选择、表头指定、规则校验、预览到 CSV 下载的完整 Web 流程；
并新增**供水分配页**：从转换结果选择可供水量列，录入灌区需求，
按**字典序最大满足率**精确求解水库 → 灌区分配方案。

## 功能与转换规则

1. **采集网页（Flask）**：输入公示页 URL，抓取并列出页面内全部 HTML 表格，
   逐个给出容错迷你预览，选择目标表格并指定**顶部 1～3 行表头**。
2. **首列固定为水库名**：正文仅首列允许 `rowspan`，跨度内向下继承水库名；
   其余正文单元格不允许任何合并。
3. **按 `rowspan` / `colspan` 展开为规则网格**：
   - 表宽 = **首行展开宽度**（首行各单元格 colspan 之和）；
   - 同一来源单元格只记录一次，表头路径不重复同一段；
   - 路径文本相同的不同列仍分别保留，不合并。
4. **完整表头路径**：沿表头各行向下拼接，分隔符为 ` / `
   （如 `水位（米） / 旬初`）。
5. **空值语义**：观测空单元格保持为空；短行缺失的网格格位同样导出空值，
   且不携带来源单元格坐标。
6. **结构错误即停**：跨度重叠、横向越界、跨越表头/正文、正文非法合并时，
   标明来源单元格位置（`R行C列`，按**原表行序及行内单元格序从 1 计数**）
   并停止转换，不产生任何记录。
7. **CSV 导出**：字段为 `水库, 表头路径, 原始文本, 来源单元格行,
   来源单元格列, 来源单元格坐标, 来源URL`，UTF-8 带 BOM，Excel 可直接打开。

## 供水分配页

1. **选择可供水量列**：在转换结果预览页按**列位置**（第 2 列起，首列固定为
   水库名）选择可供水量列。该列每个正文行读出一座水库：
   - 最多 **6** 座水库；
   - 数值须为**非负整数**，单位统一按**万立方米**处理；
   - **同名水库拒绝**（rowspan 继承导致的重复名同样会被拒绝，需先汇总为
     每库一行），违规时标明水库名与来源单元格坐标。
2. **录入灌区**：页面上录入最多 **12** 个灌区，每个灌区包含名称、
   **正整数**需水量（万立方米）及**可供水库**勾选项；允许不勾选任何水库
   （无水源灌区满足率恒为 0，其余灌区仍照常优化）。
3. **分配约束**：水只能沿指定的「水库 → 灌区」关系分配；每座水库供水总量
   不超过其可供水量，每个灌区所得不超过其需水量。
4. **优化目标**：满足率 = 所得水量 ÷ 需水量。将全部灌区满足率**升序**排成
   向量，精确求该向量的**字典序最大值**（先提高最低满足率，再依次提高
   后续项）。
5. **结果展示**：升序满足率向量、各灌区满足率与缺口、水库 → 灌区分配
   矩阵，**均以最简分数表示**（分母为 1 时写作整数）；最优分配不唯一时
   任取一组实现该向量的方案。

### 求解算法（精确有理数）

`app/allocation.py` 全程使用 `fractions.Fraction`，无浮点误差：

1. **渐进注水求满足率**：每轮为未冻结灌区求最大公共满足率 λ。由最大流
   最小割，枚举水库子集 Z（≤ 6 座共 64 个子集）：
   `λ = min_Z ( C(Z) − F(Z) ) / D(Z)`，其中 C(Z) 为 Z 内水库可供水量之和、
   D(Z) 为可供水库全落在 Z 内的未冻结灌区需水量之和、F(Z) 为已冻结灌区
   锁定水量之和；λ 同时不超过 1。取最紧子集之并，落在并集内的灌区本轮
   冻结在 λ（其水源容量已占满，不可能再提高）。每轮至少冻结一个灌区，
   无水源灌区第一轮即以 λ = 0 冻结。
2. **精确最大流还原分配**：全部冻结后，以 `满足率 × 需水量` 作为各灌区
   汇点容量，跑一次 Fraction 版 Dinic 最大流，得到实现该满足率向量的
   一组水库 → 灌区分配水量。

## 目录结构

```
.
├── app/
│   ├── web.py                 # Flask 路由：抓取/选择/转换/下载 + 供水分配
│   ├── grid_parser.py         # 合并单元格展开、校验、表头路径、记录生成
│   ├── allocation.py          # 可供水量列解析、灌区校验、字典序最大满足率求解
│   ├── templates/             # index/select/preview/allocate/allocate_result/error 页面
│   └── static/
│       ├── style.css
│       └── samples/
│           ├── notice.html        # 标准示例公示页（含合法 rowspan/空值/短行）
│           ├── notice_error.html  # 错误示例页（跨边界 rowspan、正文非法 colspan）
│           └── notice_supply.html # 可供水量示例页（每库一行、整数万立方米）
├── tests/                     # 55 个 unittest 用例（解析规则 + 分配算法 + Web 端到端）
├── requirements.txt
├── Dockerfile
├── docker-compose.yml
└── run_dev.sh                 # 本地无 Docker 时的开发启动脚本
```

## 方式一：Docker Compose（推荐，交付即启）

```bash
docker compose up --build
# 浏览器打开
http://localhost:8000
```

首页点击「使用标准示例页」即可离线演示完整链路；
「使用错误示例页」演示结构错误的定位与停止转换；
「使用可供水量示例页」演示供水分配全流程。

## 方式二：本地 Python 运行

需要 Python 3.11+：

```bash
python3 -m pip install -r requirements.txt
./run_dev.sh            # 等价于 gunicorn app.web:app ，监听 8000
# 或开发热更：
FLASK_APP=app.web flask run --host 0.0.0.0 --port 8000
```

## 演示路径

### 采集转换

1. 打开 `http://localhost:8000/`，点击「使用标准示例页」；
2. 选择表格、表头行数保持 **2 行**，点击「转换此表格」；
3. 预览 35 条观测记录（5 条正文行 × 7 个观测列）、完整表头路径、
   来源坐标；注意青山水库的 rowspan 继承、碧河空单元格、云岭短行空值；
4. 点击「下载 CSV」获得带 BOM 的入库文件；
5. 返回首页用「错误示例页」分别转换两张表，观察带 `R行C列` 的报错与停止行为。

### 供水分配

1. 首页点击「使用可供水量示例页」，转换表 1（2 行表头）；
2. 在转换结果页底部「第四步：供水分配」选择
   **第 2 列：可供水量（万立方米） / 旬可供水量**，进入供水分配页；
3. 水源清单读出 4 座水库（90 / 60 / 45 / 35 万立方米）；点击
   「填充演示灌区」自动录入 4 个灌区（含一个无水源灌区），也可手工增删改；
4. 点击「求解最优分配」，得到升序满足率向量
   **( 0 ≤ 3/4 ≤ 9/10 ≤ 1 )**、各灌区满足率与缺口、以及水库 → 灌区
   分配矩阵（全部以分数表示）；
5. 对照实验：用「标准示例页」的水位列（小数）作为可供水量列，会被
   「非负整数」校验拒绝；每库多行的表格会触发「同名水库拒绝」。

## 设计约束与说明

- 只解析目标 `<table>` 的直属 `<tr>/<td>/<th>`，嵌套表格不会串入。
- `rowspan=0`、非法跨度属性按浏览器约定按 1 处理；垂直方向超出表格
  底部的 rowspan 按浏览器约定裁剪，**横向**超出表宽判越界报错。
- 抓取缓存与分配会话均为进程内字典（TTL 30 分钟、上限 50 条），因此
  Compose 使用单 gunicorn worker + 多线程；如需多 worker 请替换为
  Redis 等共享存储。
- 抓取远程页面时携带自定义 User-Agent、15 秒超时，并按响应头/内容
  推断编码，适配中文公示页常见的 GB 系编码。
- 分配求解不引入任何第三方库（仅用标准库 `fractions`），满足率向量
  唯一，分配方案不唯一时任取其一；灌区同名按重复录入拒绝，避免结果
  表歧义。
